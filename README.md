# LMS — права доступа в DRF

Домашнее задание №31: **«Права доступа в DRF»**.

Рабочая ветка:

```text
31-drf-permissions
```

## Описание

В проекте реализованы:

* CRUD для пользователей;
* регистрация пользователей;
* JWT-аутентификация;
* разграничение прав доступа для пользователей и модераторов;
* привязка курсов и уроков к владельцу;
* фильтрация объектов по владельцу;
* группа `Модераторы`;
* фикстура для создания группы модераторов;
* отдельные permissions для проверки владельца, модератора и пользователя профиля;
* тесты JWT, регистрации и прав доступа.

Дополнительно реализованы ограничения для профилей пользователей:

* авторизованный пользователь может просматривать любой профиль;
* редактировать и удалять можно только собственный профиль;
* при просмотре чужого профиля скрываются фамилия и история платежей;
* пароль пользователя не возвращается API.

## JWT-аутентификация

Для JWT используется пакет:

```text
djangorestframework-simplejwt
```

JWT-аутентификация настроена глобально в `REST_FRAMEWORK`.

### Получение токенов

```http
POST /api/token/
```

Тело запроса:

```json
{
    "email": "user@example.com",
    "password": "password"
}
```

В ответ возвращаются:

```text
access
refresh
```

### Обновление access-токена

```http
POST /api/token/refresh/
```

Тело запроса:

```json
{
    "refresh": "<refresh_token>"
}
```

Для доступа к защищённым эндпоинтам используется заголовок:

```text
Authorization: Bearer <access_token>
```

---

## Регистрация

Регистрация доступна без авторизации:

```http
POST /api/users/register/
```

При регистрации:

* проверяется уникальность email;
* пароль сохраняется в хешированном виде;
* пароль не возвращается в API;
* повторная регистрация с существующим email возвращает ошибку `400 Bad Request`.

---

## Пользователи

Основные эндпоинты:

| URL                    | Метод     | Доступ                      |
| ---------------------- | --------- | --------------------------- |
| `/api/users/register/` | POST      | Без авторизации             |
| `/api/users/`          | GET       | Авторизованные пользователи |
| `/api/users/<pk>/`     | GET       | Авторизованные пользователи |
| `/api/users/<pk>/`     | PUT/PATCH | Только владелец профиля     |
| `/api/users/<pk>/`     | DELETE    | Только владелец профиля     |
| `/api/token/`          | POST      | Без авторизации             |
| `/api/token/refresh/`  | POST      | Без авторизации             |

При просмотре чужого профиля не отображаются:

```text
password
last_name
payments
```

## Владельцы курсов и уроков

В модели `Course` добавлено поле владельца:

```python
owner = models.ForeignKey(...)
```

В модели `Lesson` также добавлено поле владельца:

```python
owner = models.ForeignKey(...)
```

Оба поля связаны с:

```python
settings.AUTH_USER_MODEL
```

При создании курса или урока владелец автоматически определяется по текущему пользователю:

```python
serializer.save(owner=self.request.user)
```

Поле `owner` нельзя изменить через API.

## Права доступа

Для разграничения доступа используются отдельные permission-классы.

### `IsModerator`

Проверяет принадлежность пользователя к группе:

```text
Модераторы
```

### `IsOwner`

Проверяет, является ли текущий пользователь владельцем курса или урока.

### `IsSelf`

Проверяет права пользователя на изменение или удаление собственного профиля.

---

## Права на курсы

Курсы реализованы через `CourseViewSet`.

Для разных `action` права задаются через:

```python
get_permissions()
```

### Обычный пользователь

Может:

* создавать курсы;
* видеть только свои курсы;
* получать только свои курсы;
* редактировать только свои курсы;
* удалять только свои курсы.

При создании курса текущий пользователь автоматически становится его владельцем.

### Модератор

Может:

* видеть все курсы;
* получать любой курс;
* редактировать любой курс.

Не может:

* создавать курсы;
* удалять курсы.

---

## Права на уроки

Уроки реализованы через:

```text
LessonListCreateAPIView
LessonRetrieveUpdateDestroyAPIView
```

### Обычный пользователь

Может:

* создавать уроки;
* видеть только свои уроки;
* получать только свои уроки;
* редактировать только свои уроки;
* удалять только свои уроки.

При создании урока текущий пользователь автоматически становится его владельцем.

Обычный пользователь может привязать новый урок только к своему курсу.

### Модератор

Может:

* видеть все уроки;
* получать любой урок;
* редактировать любой урок.

Не может:

* создавать уроки;
* удалять уроки.

---

## Матрица прав для курсов и уроков

| Операция         | Анонимный | Владелец    | Другой пользователь          | Модератор |
| ---------------- | --------- | ----------- | ---------------------------- | --------- |
| Получение списка | 401       | Только свои | Только свои                  | Все       |
| Просмотр объекта | 401       | Разрешено   | Недоступно                   | Разрешено |
| Создание         | 401       | Разрешено   | Разрешено для своего объекта | Запрещено |
| PUT/PATCH        | 401       | Разрешено   | Недоступно                   | Разрешено |
| DELETE           | 401       | Разрешено   | Недоступно                   | Запрещено |

Для списка объектов используется фильтрация через `get_queryset()`, поэтому обычный пользователь не получает чужие курсы и уроки.

## Группа модераторов

В проекте используется Django-группа:

```text
Модераторы
```

Фикстура находится в:

```text
users/fixtures/groups.json
```

Загрузить её можно командой:

```bash
python manage.py loaddata groups.json
```

Пользователь добавляется в группу `Модераторы` через Django Admin.

Проверка принадлежности к группе выполняется через:

```python
request.user.groups.filter(name="Модераторы").exists()
```
