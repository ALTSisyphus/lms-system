# LMS System

LMS System — backend-приложение для платформы онлайн-обучения, разработанное на Django и Django REST Framework.

Проект предоставляет REST API для управления пользователями, курсами и уроками, подписок на обновления курсов и оплаты обучения через Stripe.

API использует JWT-аутентификацию, систему прав доступа, пагинацию, фильтрацию и автоматическую OpenAPI-документацию.

## Возможности проекта

### Пользователи

В проекте реализована собственная модель пользователя с авторизацией по email.

Доступны:

* регистрация пользователя;
* получение JWT access/refresh токенов;
* обновление JWT access-токена;
* просмотр списка пользователей;
* просмотр своего профиля;
* редактирование своего профиля;
* удаление своей учётной записи;
* отображение истории платежей пользователя.

### Курсы

Для курсов реализован полноценный CRUD:

* создание курса;
* получение списка курсов;
* просмотр отдельного курса;
* изменение курса;
* удаление курса.

Курс содержит:

* владельца;
* название;
* описание;
* изображение-превью;
* стоимость.

Обычный пользователь работает только со своими материалами.

Модераторы могут просматривать и редактировать учебные материалы, но не могут создавать или удалять их.

### Уроки

В рамках курса можно создавать и управлять уроками.

Урок содержит:

* владельца;
* курс;
* название;
* описание;
* изображение-превью;
* ссылку на видео.

Для ссылок на видео реализована валидация: разрешены ссылки только на YouTube.

### Подписки

Пользователь может подписаться на обновления выбранного курса и отменить подписку.

Для пары:

```text
пользователь + курс
```

может существовать только одна подписка.

В API курса отображается информация о том, подписан ли текущий пользователь на этот курс.

### Пагинация

Списки курсов и уроков поддерживают пагинацию.

Поддерживается параметр:

```text
page_size
```

с ограничением максимального размера страницы.

### Платежи

В проекте реализована модель платежей.

Платёж связан с:

* пользователем;
* курсом или уроком;
* суммой;
* датой;
* способом оплаты.

Для списка платежей доступны фильтры:

```text
paid_course
paid_lesson
payment_method
```

Также поддерживается сортировка по:

```text
payment_date
```

### Оплата курсов через Stripe

Проект интегрирован со Stripe Checkout.

При создании платежа сервер автоматически выполняет следующий процесс:

```text
Курс
  ↓
Stripe Product
  ↓
Stripe Price
  ↓
Stripe Checkout Session
  ↓
Payment в базе данных
  ↓
Ссылка на страницу оплаты
```

Для каждого Stripe-платежа сохраняются:

* Stripe Product ID;
* Stripe Price ID;
* Stripe Checkout Session ID;
* ссылка на оплату;
* статус платежа.

Стоимость курса хранится в рублях, а при передаче в Stripe преобразуется в копейки.

Например:

```text
1500.00 ₽ → 150000
```

После создания платежа API возвращает пользователю ссылку на Stripe Checkout.

Также реализована проверка актуального статуса платежа через Stripe Checkout Session Retrieve. Полученный статус синхронизируется с локальной моделью платежа.

Все обращения к Stripe вынесены в отдельный сервисный слой.

## Безопасность

В проекте используются:

* JWT-аутентификация;
* разграничение прав владельцев и модераторов;
* проверка доступа к пользовательским данным;
* защита платежей от доступа других пользователей;
* переменные окружения для секретных параметров;
* исключение `.env` из Git;
* обработка ошибок Stripe без передачи секретных данных клиенту.

Stripe Secret Key не хранится в исходном коде.

## API-документация

Документация API генерируется с помощью `drf-spectacular`.

После запуска проекта доступны:

### Swagger UI

```text
http://127.0.0.1:8000/api/docs/
```

### ReDoc

```text
http://127.0.0.1:8000/api/redoc/
```

### OpenAPI Schema

```text
http://127.0.0.1:8000/api/schema/
```

Документация содержит описание:

* параметров запросов;
* request body;
* response body;
* ошибок;
* фильтрации;
* сортировки;
* пагинации;
* JWT-аутентификации;
* Stripe endpoints.

Проверить OpenAPI schema можно командой:

```bash
python manage.py spectacular --file schema.yaml --validate
```

## Основные API endpoints

### Аутентификация

```text
POST /api/token/
POST /api/token/refresh/
```

### Пользователи

```text
POST /api/users/register/
GET  /api/users/
GET  /api/users/{id}/
PUT  /api/users/{id}/
PATCH /api/users/{id}/
DELETE /api/users/{id}/
```

### Курсы

```text
GET    /api/courses/
POST   /api/courses/
GET    /api/courses/{id}/
PUT    /api/courses/{id}/
PATCH  /api/courses/{id}/
DELETE /api/courses/{id}/
```

### Уроки

```text
GET    /api/lessons/
POST   /api/lessons/
GET    /api/lessons/{id}/
PUT    /api/lessons/{id}/
PATCH  /api/lessons/{id}/
DELETE /api/lessons/{id}/
```

### Подписки

```text
POST /api/subscriptions/
```

Пример запроса:

```json
{
  "course": 1
}
```

Повторный запрос переключает состояние подписки.

### Платежи

```text
GET  /api/payments/
POST /api/payments/
```

Для создания Stripe-платежа передаётся курс:

```json
{
  "course": 1
}
```

API создаёт необходимые сущности в Stripe, сохраняет данные платежа в базе и возвращает Checkout URL.

### Проверка статуса платежа

```text
GET /api/payments/{id}/status/
```

Endpoint получает актуальное состояние Checkout Session в Stripe и синхронизирует статус локального платежа.
